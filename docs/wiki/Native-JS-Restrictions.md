# Native JS 제약과 차이점

Native JS는 변수와 함수를 **미리 정해진 자리**에 두고 **직접 호출**하도록 변환합니다. 그 덕분에 빠르지만, 이 전제를 깨는 코드 몇 가지는 변환하지 않고 오류로 알려줍니다.

## 변환할수 없는 코드

| 제약 | 예 | 오류 메시지 |
| --- | --- | --- |
| **변수/함수 삭제** | `x =` | `Native JS 제약: 변수/함수 삭제('x =')를 쓸수 없습니다.` |
| **내장 함수/상수와 프로그램이 제공하는 함수의 재정의·대입** | `add = 1`, `func mul`, `5 = true`, `for add 'abc'` | `Native JS 제약: 내장 함수/상수 'add'을/를 대입할수 없습니다.` |
| **goto로 블록(if, while, repeat, for) 안쪽에 들어가기** | `goto inner` (inner가 `if` 안에 있음) | `Native JS 제약: goto로 블록(if, while, repeat, for) 안쪽으로 들어갈수 없습니다.` |
| 블록 구조 오류 (짝이 없는 `end` 등) | | 실행 전에 알려줌 ([아래](#블록-구조-오류는-실행-전에-알려줍니다)) |
| **구조체 생성자 안에서 구조체 정의** (Jyuno 1.5.1부터) | `struct a` 안의 `struct b` | `Native JS 제약: 구조체(struct) 안에서 구조체를 정의할수 없습니다.` |

이 검사는 Jyuno 라이브러리의 `ScriptAnalysis.CheckNativeJs(globals)`가 하므로, 편집기나 다른 도구에서도 같은 결과를 얻을수 있습니다.

### 허용되는 것

- **프로그램이 제공하는 변수**(`console.title` 등)에 값을 대입하는 것은 재정의가 아니므로 괜찮습니다.
- **같은 블록이나 바깥 블록으로 가는 goto**는 모두 됩니다. 반복문 탈출, 뒤로 돌아가는 루프, `goto else`/`goto end`, 레이블 변수나 계산한 값으로 하는 이동도 그 값이 갈수 있는 줄이면 됩니다.

```jyuno
i = 0
top:
i = add i 1
if (less i 5)
    goto top        ← 바깥 블록의 레이블: 괜찮음
end
console.writeline i
```

### 실행 중에 나는 제약 오류

이동할 줄을 계산하는 goto는 변환할 때 대상을 다 알수 없습니다. 실행 중에 블록 안쪽 줄로 가려고 하면 그 자리에서 오류가 납니다.

```
Native JS 제약: goto로 8번 줄로 이동할수 없습니다. (같은 블록이나 바깥 블록의 레이블/줄로만 이동할수 있습니다)
```

함수 안팎을 넘나드는 goto처럼 인터프리터에서도 오류인 경우는 인터프리터와 같은 메시지를 냅니다.

구조체 값을 담은 변수의 **멤버 이름**(`p.x`, `p.show`)을 그 변수가 구조체 값을 담고 있는 동안 `func`, `local`, `param`, `struct`로 다시 정의하면 그 자리에서 오류가 납니다. (일반 대입 `p.x = 5`는 필드를 바꾸는 것이므로 괜찮습니다)

```jyuno
p = point 1 2
func p.show          ← 실행 중 오류
    ...
endfunc
```

```
Native JS 제약: 구조체 값의 멤버 이름 'p.show'을/를 다시 정의할수 없습니다.
```

인터프리터에서는 이 경우 멤버 이름이 구조체 값과 따로 노는 이름이 되는데, Native JS는 멤버 이름을 따로 만들지 않고 변수에 담긴 구조체 값의 필드로 바로 찾기 때문입니다.

## 왜 이런 제약이 있나요?

| 제약 | 이유 |
| --- | --- |
| 블록 안으로 들어가는 goto | JS에는 블록 **안쪽으로** 뛰어드는 점프가 없습니다. 허용하려면 프로그램 전체를 하나의 상태 기계(`switch`)로 만들어야 해서, goto를 쓰지 않는 코드까지 모두 느려집니다. |
| 내장 함수 재정의 | `add`가 언제든 다른 함수로 바뀔수 있다면 `add2(a, b)`처럼 직접 부를수 없고, 매번 이름을 찾아야 합니다. 재정의를 막으면 모든 내장 함수 호출이 빠른 경로를 탑니다. |
| 삭제 | 삭제가 있으면 "이 변수는 여기서 반드시 있다"는 분석이 깨지고, 모든 변수 읽기에 검사가 필요해집니다. |
| 구조체 안의 구조체 | 구조체마다 필드 모양이 고정된 JS 클래스를 파일 맨 위에 하나씩 만드는데, 생성자 안에서 만든 구조체는 생성자를 부를 때마다 바깥 영역이 달라져 하나의 클래스로 만들수 없습니다. |
| 멤버 이름 재정의 | 멤버 이름(`p.x`)을 따로 저장하지 않고 쓰는 자리에서 `p`의 필드로 찾기 때문에, 같은 이름의 다른 정의와 함께 둘 곳이 없습니다. |

연구용 프로토타입은 재정의와 삭제도 지원했습니다(재정의된 이름만 느린 경로로 처리). 실제 도입(Jyuno 1.4.0, JyunoSdk 0.2.0)에서는 구현을 단순하게 하고 모든 호출을 빠른 경로로 만들기 위해 제약으로 바꿨습니다.

## 실제 코드에 미치는 영향

연구 당시 **JyunoWeb 채점 문제 풀이 53개, 플레이그라운드 예제 19개, Jyuno.Tests 스크립트 299개** 중 goto 제약에 걸린 코드는 **0개**였습니다. 대부분의 Jyuno 코드는 고치지 않고 그대로 변환됩니다.

## 제약이 아닌 차이

### 블록 구조 오류는 실행 전에 알려줍니다

인터프리터는 `end`가 남는 것 같은 구조 오류도 **그 줄에 도달해야** 보고합니다. Native JS는 **변환할 때** 보고하므로, 그 전까지의 출력이 나오지 않습니다. 메시지와 줄 번호는 같습니다. Jyuno.Tests 299개에서 나온 유일한 차이가 이것입니다. 학습용으로는 일찍 알려주는 편이 낫다고 판단했습니다.

### 그 밖의 알려진 차이

- **명령어**: `file.*`, `directory.*`는 지원하지 않습니다.
- **`console.read`**: C#의 `char` 대신 한 글자 문자열을 돌려줍니다.
- **초월 함수**: `math.sin`, `math.pow`, `math.log` 등은 V8과 .NET의 수학 라이브러리가 달라 **마지막 비트**가 다를수 있습니다. 무작위 테스트에서는 나오지 않았지만 보장하지는 않습니다.
- **문자열 서식**: 자주 쓰는 지정자(`D`, `X`, `F`, `N`, `P`, `E`, `G`, `R`)를 구현했습니다. 드문 사용자 지정 서식은 다를수 있습니다.
- **난수**: `math.random`, `array.shuffle`은 `Math.random()`, `math.csprng`는 `crypto.getRandomValues()`를 씁니다. 범위와 결과 타입(정수/실수)은 같지만, 뽑히는 값은 당연히 다릅니다.
- **대소문자 변환**: `string.toupper`, `string.tolower`, `string.equals ... true`는 .NET과 같은 단순 변환(한 글자 → 한 글자)을 따릅니다. 다만 브라우저/Node.js와 .NET이 아는 유니코드 버전이 다르면, 가장 최근에 추가된 문자는 다르게 바뀔수 있습니다.
- **큰 정수**: ±2^53을 넘는 정수도 64비트로 정확하게 계산하지만, BigInt 경로라 느립니다.
- **호스트 함수**: C#으로 만든 호스트 함수는 JS로 다시 구현해야 합니다. ([[사용하기|Native-JS-Usage#4-호스트-함수와-변수]])
